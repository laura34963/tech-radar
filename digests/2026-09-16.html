GHSA-353f-x4gh-cqq8: nokogiri

Nokogiri 更新內建的 libxml2 以修補多個 upstream 安全漏洞。

Why it matters

Rails 應用程式普遍依賴 Nokogiri 進行 HTML/XML 消毒與解析（如 sanitize 與各類爬蟲模組），未修補的解析器可能遭受 DoS 或記憶體破壞攻擊。

展開詳細

GHSA-68xg-gqqm-vgj8: puma

Puma 存在 HTTP 請求／回應走私（Request/Response Smuggling）漏洞。

Why it matters

在典型的 Nginx + Puma 架構下，請求走私可讓攻擊者繞過前端身分認證、毒化共用快取或劫持其他合法使用者的 HTTP 工作階段。

Recommended action

升級 Gemfile 中的 puma 至安全修復版本，並確認前端 Nginx 已啟用嚴格的 HTTP 標頭驗證規則。

展開詳細

Puma 在解析特製的畸形 HTTP/1.1 標頭（如 Content-Length 與 Transfer-Encoding 衝突）時，與前端的反向代理伺服器（如 Nginx）產生語義解析分歧。攻擊者可利用請求邊界的不一致，在後端連線池中夾帶未經授權的請求。

GHSA-p92q-9vqr-4j8v: axios

Axios 在 Node.js 環境中遇 HTTP 至 HTTPS 重導向時會洩漏 Proxy-Authorization 標頭。

Why it matters

若 Node.js 或 Next.js 伺服器端透過需要帳密驗證的代理伺服器呼叫外部第三方 API，外部端點伺服器將可能側錄到公司內部的 Proxy 機密認證資訊。

Recommended action

將專案中的 axios 套件更新至修復 Proxy-Authorization 洩漏問題的最新版本。

展開詳細

此漏洞發生於 Axios 的 Node.js HTTP adapter 在處理 3xx 轉址時，未在協定切換（HTTP 到 HTTPS）或切換至未經代理的目標時清除 Proxy 認證標頭。這導致原先應僅發送給 Forward Proxy 的憑證被直接附加在請求中送至原始目標伺服器。

Axios 的 shouldBypassProxy 未支援 IPv4-mapped IPv6，導致 NO_PROXY 被繞過。

Why it matters

若 Next.js 或 Node.js 服務透過 Forward Proxy 存取外部網路，同時仰賴 NO_PROXY 保護內網微服務，攻擊者可誘使伺服器將原本應留在內網的機密請求轉送至代理伺服器造成資訊外洩。

Why it matters

在 Node.js 與 Next.js 伺服器端環境中，若依賴 NO_PROXY 阻絕本地端或 Proxy 路由，攻擊者可能藉由其他 127.x.x.x 位址發動 SSRF 攻擊或引發存取控制混淆。

No Extensions? You Forgot One: Writing Shared Objects to RCE via SQLite's dbpage

研究員展示利用 SQLite 的 sqlite_dbpage 虛擬資料表在磁碟寫入 .so 檔並達成 RCE。

Why it matters

若後端 Rails、Python 或 Node.js 服務使用 SQLite 且存在 SQL Injection，防禦者原先依賴「延伸模組已禁用」的縱深防禦將被繞過，直接被升級為遠端代碼執行。

Recommended action

在正式環境編譯或使用 SQLite 時，確保加上 SQLITE_OMIT_DBPAGE 參數停用該虛擬資料表，並嚴格阻斷未參數化的 SQL 查詢。

展開詳細

即使目標環境關閉了 SQLite 的動態延伸模組載入（load_extension），攻擊者若握有任意 SQL 執行能力，仍可透過 sqlite_dbpage 操縱資料庫頁面寫入合法的 ELF Shared Object。隨後搭配 Node.js、Ruby 或 Python 執行環境的動態載入行為，即可劫持執行流程獲取本機 Shell。
